Buyer Reports Windows 執行檔使用說明

一、資料整理規則與前置條件

DPS：
1. 檔名需包含 DPS 字眼；程式會依活頁簿順序抓第一張名稱包含 DPS 的工作表作為來源。
2. 表頭列需包含：Line、W/O，以及 buyer_reports.ini 內設定的其中一個 DPS 料號欄別名。
3. 日期欄必須是 Excel 日期格式；若日期是用公式累加產生也可以，但檔案需經 Excel 計算並儲存，讓程式讀得到日期值。
4. 正常格式下，每個日期應該有兩欄，也就是 D / N 兩班。程式預設會把同一天的欄位加總。
5. 料號欄預設可使用 AVTC P/N、P/N 或 Model。
6. 料號結尾帶 * 的資料預設會被排除。
7. AVTC DPS 維持原本邏輯：取第一份格式正確的檔案。
8. RAKEN DPS 會合併 RAKEN 資料夾內所有格式正確的 DPS 檔，同料號同日期累加。

PP：
1. 檔名需包含 PP 字眼。
2. 程式會依活頁簿順序抓第一張名稱包含 PP 或 Data 且含樞紐分析表的工作表，作為欄位版面與客戶排序來源。
3. 該樞紐分析表對應的 pivot cache 內必須有 Plan、Customer、Model，並有名稱包含 Part Number 的料號欄位。
4. Plan 欄位的值預設必須是 Production Input，程式才會納入計算。
5. 週別與月份欄位需符合 Excel 樞紐表 / pivot cache 的格式。
6. 跨月但同週的項目會合併加總，例如 WK36 和 WK36 Sep 會寫進同一個 WK36。
7. 程式會抓 pivot cache 的更新日所在週再減一，作為可見版面起始週。例如更新日是 2026-07-31，屬於第 31 週，所以可見版面會從 WK30 開始銜接。
8. 起始週以前、同年度的 WK 週欄會從 pivot cache 補齊輸出，即使來源樞紐欄位清單未勾選也會顯示在整理後檔案中，但不納入 total。
9. 來源樞紐報表中被隱藏的時間欄位也會納入計算，並在整理後檔案中顯示出來。
10. 沒有週明細的月份會直接以月份欄位作為輸出。

DPS+PP：
1. 同一個客戶資料夾內 DPS 與 PP 都能成功讀取時，會額外產出 DPS+PP.xlsx。
2. 週別採 buyer week：週六到週五。例如 2026-08-08 到 2026-08-14 是 WK33。
3. 自動判斷目前週時，週六到週四用執行日所在 buyer week；週五會提前使用隔天週六的新 buyer week。例如 2026-08-15 到 2026-08-20 會用 WK34，2026-08-21 會提前用 WK35。
4. AVTC 預設 DPS 保留含目前 buyer week 共 5 週；例如目前 WK34，DPS 到 WK38，PP 從 WK39 開始。
5. RAKEN 的 DPS 保留週數可在 INI 設定；雙擊 exe 時若 input/RAKEN 有 Excel，會先跳出視窗讓使用者選擇 RAKEN 保留 2 / 3 / 4 週。
6. DPS 若在 PP 接續週含之後仍有數字，AVTC 會併入 DPS 保留週的最後一天；RAKEN 會排除截止日之後的 DPS，由 PP 接續週接手，避免重複。
7. 若來源檔內有 BOM1 工作表，程式會用 BOM1 的 B 欄料號對應 H 欄 vendor 寫入 BOM；若沒有，BOM 欄留空。

CTB：
1. 同一個客戶資料夾內若有 BOM1、open po、over shortage 工作表，且本次 DPS+PP.xlsx 成功產出，會額外產出 CTB.xlsx。
2. BOM1 用來將 DPS+PP 的成品需求依 USE 展開成子件需求。
3. over shortage 用來取得 shortage 起始值；來源 sheet 必須有 Part No 與 OVER SHORTAGE / Over Shortage 欄，程式會直接使用該欄作為 CTB 的 OVER SHORTAGE / balance 起始值。
4. open po 可用 Item 或 Part No. 搭配 Supplier Site 或 Trading Vendor 對應料號與 Supplier site，
   並讀取 Quantity Due 或 Qty UnRCV、Need By Date；Supplier 欄位可使用 Supplier 或 Shipping Site Code，
   產出 ETA / PO Remain 列。
5. CTB 的 D 欄 key 由 C 欄 Part No + E 欄 Code 組成；E 欄 Code 來自 open po 的 Supplier Site。
6. ETA 會逐筆模擬 Balance，依 Supplier Site 設定的提前天數將 Quantity Due 放到第一個負值期間之前；未個別設定時預設往前 15 個日曆日。若整個期間沒有負值，才使用該筆 Need By Date。
7. Balance row 會寫入 Excel 公式：第一期沿用既有起算邏輯，後續期間為上一期 Balance + 上一期 ETA - 本期 Demand - 本期 other；使用者開啟檔案後修改 ETA / other 數字，後續 Balance 會由 Excel 連動重算。
8. 若同一個客戶資料夾內有原始 CTB 工作表，程式會沿用該 CTB 的表頭、日期欄、列順序與格式作為版型，但 A:M 資料列會依自動化規則重建，不直接抄原始 CTB 的人工欄位；若沒有原始 CTB，仍會用程式新建版面產出。
9. CTB 主表的 OVER SHORTAGE 與 Balance 期間欄、輔助頁 over shortage 的 Over Shortage 欄若為負數，會以紅色字體顯示。
10. CTB A:M 欄位規則：A/G/H/I 保留欄位但資料列空白；B 由 BOM1 的 Model+USE 組成，找不到來源則空白；D= C+E，ETA row 會寫入公式；E 取 open po 的 Supplier Site；F 只有在 BOM1 vendor 是乾淨來源時填入，若是反查 CTB 的公式或找不到來源則空白；J 用 SUMIF 從 over shortage 的 OVER SHORTAGE / Over Shortage 欄查回；K 在 ETA row 用 SUMIF 加總 open po Quantity Due，在 Balance row 使用公式 J OVER SHORTAGE - by-day 最後一天的 Balance；L total 會加總該 ETA row 的日期區數量；M 保留 Demand / ETA / other / Balance 等 row type。

二、資料夾結構

請保持整個 BuyerReports 資料夾放在一起，不要只單獨移動 exe。

BuyerReports/
  BuyerReports.exe
  _internal/
  buyer_reports.ini
  ctb_eta_days.ini（可選；不存在時第一次執行會自動建立）
  input/
    AVTC/
    RAKEN/
  output/
    AVTC/
    RAKEN/
  Windows執行檔(exe)使用說明.txt

注意：輸入資料夾名稱是 input，請不要改名。
注意：AVTC 檔案請放 input/AVTC，RAKEN 檔案請放 input/RAKEN。
注意：buyer_reports.ini 是 sheet / 欄位偵測關鍵字設定，請和 BuyerReports.exe 放在同一層。
注意：ctb_eta_days.ini 是 CTB ETA Supplier Site 提前天數設定，請和 BuyerReports.exe 放在同一層；若檔案不存在，程式會自動建立。
注意：如果收到的是 zip 壓縮檔，請先完整解壓縮，不要在壓縮檔視窗內直接雙擊 BuyerReports.exe。

三、使用步驟

1. 如果收到的是 zip 壓縮檔，請先按右鍵選擇「全部解壓縮」。

2. 進入解壓後的 BuyerReports 資料夾。

3. 把 DPS 與 PP 來源 Excel 檔放進對應資料夾。
   - AVTC 檔案放進 input/AVTC
   - RAKEN 檔案放進 input/RAKEN
   - DPS 檔名需包含 DPS
   - PP 檔名需包含 PP
   - 若要產 CTB，同一個客戶資料夾也需有含 BOM1、open po、over shortage 工作表的 Excel

4. 關閉已開啟的輸出檔，避免 Excel 鎖住檔案。

5. 雙擊 BuyerReports.exe。
   若 Windows 顯示 SmartScreen 警告，請確認檔案來源可信後，點「更多資訊」再點「仍要執行」。
   首先請選擇本次要處理的客戶：AVTC、RAKEN 或「全部執行」。選擇 AVTC 時會略過 RAKEN 週次設定。
   選擇 RAKEN 或「全部執行」時，若 input/RAKEN 內有 Excel，會出現 RAKEN DPS+PP 週數選擇視窗；請選擇 2 週、3 週或 4 週，此選項只影響 output/RAKEN/DPS+PP.xlsx。
   若選定客戶有 CTB 來源，接著會出現 CTB ETA Supplier site 設定視窗。
   已確認區與新偵測區的 Supplier site 都可以直接修改提前天數；雙擊數字後修改，按 Enter 會出現確認視窗。
   表格會顯示 Supplier、Supplier site、備註、提前天數與狀態；備註欄可雙擊後直接輸入文字。
   可用「搜尋 Supplier site」、「搜尋 Supplier」、「搜尋備註」三個欄位快速篩選；搜尋可輸入繁體中文、簡體中文、英文、數字，例如輸入 OL 可找到包含 OL 的項目。
   輸入兩個連續星號 `**` 可代表任意長度的文字，例如輸入 CN**SIO 可找到 CNF22556V-WIESIO；單一星號 `*` 會視為一般文字。
   清單支援 Ctrl 多選、Shift 連續選取及 Ctrl+A 全選；輸入選取 Supplier site 的提前天數後，可按「套用選取項目」。
   「全部套用預設值」按下後會先出現確認視窗；確認後才會將清單內所有 Supplier site 套用目前預設值，預設為 15 天。
   尚未完成設定的新偵測 Supplier site 只會在狀態欄以紅底標示，完成套用後恢復一般底色。
   Supplier site 表頭的「隱藏」按鈕可收縮該欄，收縮後只留下紅底「展開」按鈕，再按即可展開。
   各欄位表頭右側的 ↑/↓ 按鈕可依 Supplier、Supplier site、備註、提前天數與狀態進行順序／倒序排列；預設會將紅底的新偵測 Supplier site 排在前面。
   若本次偵測到新的 Supplier site，會先顯示警告視窗，標題與項目清單之間以空白行分隔。
   設定完成後按「確定並開始執行」才會產出報表；按「取消執行」則取消本次執行。
   執行時會顯示階段式進度條。

6. 執行完成後，到對應 output 資料夾取得：
   - output/AVTC/DPS整理後.xlsx
   - output/AVTC/PP整理後.xlsx
   - output/AVTC/DPS+PP.xlsx
   - output/AVTC/CTB.xlsx
   - output/RAKEN/DPS整理後.xlsx
   - output/RAKEN/PP整理後.xlsx
   - output/RAKEN/DPS+PP.xlsx
   - output/RAKEN/CTB.xlsx
   實際會產出哪些檔案，取決於該客戶資料夾內是否有對應來源檔。

7. 每次執行都會在對應的客戶 output 資料夾產生 log，例如 output/RAKEN/log。
   如果某一種報表格式錯誤，工具會略過該報表並繼續嘗試另一種報表。
   若有報表未產出，請把 log 交給維護者確認原因。

四、偵測關鍵字設定

BuyerReports.exe 會讀取同層的 buyer_reports.ini。
預設內容如下：

[sheet_detection]
dps_sheet_keywords = DPS
pp_sheet_keywords = PP, Data

[dps]
part_number_headers = AVTC P/N, P/N, Model

[pp]
part_number_field_keywords = Part Number

[customers]
names = AVTC, RAKEN

[customer.AVTC]
dps_mode = first_valid
pp_mode = first_valid
dps_drop_zero_total_rows = false
dps_trim_trailing_zero_dates = false
dps_pp_dps_weeks_ahead = 5
dps_pp_late_dps_mode = merge_to_cutoff

[customer.RAKEN]
dps_mode = merge_all
pp_mode = first_valid
dps_drop_zero_total_rows = true
dps_trim_trailing_zero_dates = true
dps_pp_dps_weeks_ahead = 2
dps_pp_late_dps_mode = drop

若未來 PP 的樞紐分析表 sheet 改成其他命名，例如 Pivot，可改成：

[sheet_detection]
pp_sheet_keywords = PP, Data, Pivot

若未來 DPS 料號欄有新表頭，例如 Buyer P/N，可改成：

[dps]
part_number_headers = AVTC P/N, P/N, Model, Buyer P/N

多個關鍵字請用逗號分隔。修改 buyer_reports.ini 後重新雙擊 BuyerReports.exe 即可，不需要重新 build。
dps_mode = first_valid 代表取第一份格式正確的 DPS。
dps_mode = merge_all 代表合併該客戶資料夾內所有格式正確的 DPS。
dps_drop_zero_total_rows = true 代表 DPS 來源列若所有日期欄都沒有非 0 數量，就不輸出該列；RAKEN 預設開啟，AVTC 預設關閉。
dps_trim_trailing_zero_dates = true 代表 DPS 輸出只列到最後一個有非 0 數量的日期；只會裁掉尾端連續空白日期，中間空白日期仍保留。RAKEN 預設開啟，AVTC 預設關閉。
料號前後的空白、實際 tab，或 Excel XML 轉義的 _x0009_ tab，會在讀取時自動清除後再合併。
dps_pp_dps_weeks_ahead 代表 DPS+PP 中 DPS 要保留幾週，會包含目前 buyer week；目前 buyer week 在自動模式下會套用週五提前使用下一週的規則。
dps_pp_late_dps_mode = merge_to_cutoff 代表 DPS 截止日之後的數字併入 DPS 最後一天；drop 代表截止日之後的 DPS 不納入 DPS+PP，由 PP 接續週接手。
Windows exe 雙擊執行時，RAKEN 的 dps_pp_dps_weeks_ahead 可由啟動畫面選擇 2 / 3 / 4 週，該次執行會以視窗選擇為準，不需修改 buyer_reports.ini。

CTB ETA Supplier site 設定：
1. ctb_eta_days.ini 的 default_lead_days 是預設提前天數，初始值為 15。
2. [supplier_site] 是已確認區，所有 Supplier site 都可以在 exe 的 ETA 設定視窗中修改。
3. [supplier_site_new] 是新偵測區，新 Supplier site 會先以預設值加入；下一次執行時會自動移到已確認區。
4. [supplier_by_site] 是 Supplier 顯示欄位，會由 open po 偵測帶入；本次未偵測到的 Supplier site 也可以手動補。
5. [note_by_site] 是備註欄位，預設空白，可直接在文字檔填寫，也可在 ETA 設定視窗雙擊備註欄修改。
6. 設定檔內但本次 open po 沒有出現的已確認 Supplier site，也會列在設定視窗中，仍可修改。
7. 設定完成後按「確定並開始執行」，修改會保存到 ctb_eta_days.ini，並套用到當次 CTB。
8. 相同 Supplier site 目前在 AVTC 與 RAKEN 共用同一個提前天數。
9. ETA 設定視窗可用 Supplier site、Supplier、備註篩選；搜尋可輸入繁體中文、簡體中文、英文、數字。新偵測且尚未完成設定的 Supplier site 只會在狀態欄顯示紅底，完成套用後恢復一般底色。

輸出檔的標題與料號欄會以文字格式寫入；數量欄與 total 會以數值格式寫入。DPS / PP 的 total 由程式先計算好，不使用 Excel 公式；CTB 主表的 OVER SHORTAGE、PO Remain、total、Demand / PO summary 與 Balance 期間欄會寫入 Excel 公式，方便使用者開檔後手動調整 ETA / other 並連動重算。PP 的 total 只從起始週開始累加，欄名會寫出起算欄，例如 total(WK31起)。DPS+PP 的 total 會加總整份 DPS+PP 期間欄。CTB 會輸出 CTB、DPS+PP、BOM1、over shortage、open po 五張工作表，方便追溯；有原始 CTB 時會套用其表頭、日期欄、列結構與格式，但 A:M 資料列會由程式依 BOM1、open po、over shortage 來源欄位重建；沒有原始 CTB 時仍可新建 CTB。

五、常見問題

1. 找不到 DPS、PP 或 CTB 來源檔
   請確認檔案已放在 input/AVTC 或 input/RAKEN，且 DPS 檔名包含 DPS、PP 檔名包含 PP。
   若要產 CTB，該客戶資料夾需另外有 BOM1、open po、over shortage 工作表；open po 可使用 Item / Quantity Due / Supplier Site / Supplier，
   或對應的 Part No. / Qty UnRCV / Trading Vendor / Shipping Site Code 欄位名稱。
   若完全沒有 CTB 來源 sheet，工具只會產出 DPS、PP、DPS+PP，不會嘗試產 CTB；若只有部分 CTB 來源，CTB 會略過並在 log 中顯示原因。

2. Windows 顯示「無法訪問指定設備、路徑或文件」
   請確認不是在 zip 壓縮檔視窗內直接執行。請先完整解壓縮，再到解壓後的 BuyerReports 資料夾內執行。

3. Microsoft Defender SmartScreen 阻擋
   請確認檔案來源可信後，點「更多資訊」再點「仍要執行」。
   也可以對 BuyerReports.exe 按右鍵，進入「內容」，若看到「解除封鎖」請勾選後套用。

4. 找不到符合規則的 DPS 或 PP 工作表
   DPS 請確認至少有一張工作表名稱包含 DPS，且內含 Line、W/O、INI 內任一 DPS 料號欄別名與日期欄。
   PP 請確認至少有一張工作表名稱包含 buyer_reports.ini 內的 PP 關鍵字，且該工作表內有樞紐分析表。

5. 只有其中一份報表產出
   代表另一份來源檔可能格式不符。請查看對應客戶 output 資料夾內的 log。
   若 output 內已有同名整理後檔案，可能是前次執行留下的舊檔，請以 log 的本次摘要為準。

6. 無法寫入 output
   請確認輸出檔沒有被 Excel 開著，或整個資料夾沒有被設為唯讀。

7. PP 數字看起來不是最新
   本工具讀取 PP 檔案內的樞紐快取。若提供者交檔前沒有 refresh 樞紐分析表，
   工具讀到的可能是舊快取。

8. 只有原始資料、沒有人工整理後工作表
   工具仍可產出報表；只是樣式會改用內建基本版面。
